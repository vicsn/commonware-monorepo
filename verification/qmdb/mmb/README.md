# Single-operation MMB verification

Tempo pins klkvr/monorepo at `789e9e5d47288b4138183e51f8d3cf1beedd8561`. Its Merkle root encodes the leaf count, the optional inactive-peak count and the bagged peaks. The default root encoding on the Commonware verification branch also includes family and bagging domain bytes. This target uses the pinned format.

[Plan](../../lean/Qmdb/Mmb/Plan.lean) specializes the pinned single-element range proof to a location. The program numbers sibling inputs in the order consumed by `merkle::proof::Blueprint` and `Subtree::reconstruct_digest`. It builds MMB node positions, right-associated hash inputs, the backward bag of active peaks and the forward prefix of inactive peaks. A height-eight subtree is born after 383 leaves. Before that ancestor is available, a complete chunk appears in the current root's pending field. A trailing partial chunk has its own digest and next-bit count.

[Blueprint](../../lean/Qmdb/Mmb/Blueprint.lean) checks the pinned Rust classifier and digest splitter. The classifier extraction records the destination of each peak push for backward bagging. For every singleton range it agrees with the peak index selected by the plan. The splitter extraction replaces its five vectors with lengths and its returned borrows with their indices and range endpoints. Lean checks the exact required length, the two length errors, each of the five returned segments, and agreement with the plan for a classified peak list with one sibling per level. Regenerate or compare the extraction with `extract-layout.py --hax /path/to/cargo-hax` using the proof toolchain's environment.

[Peaks](../../lean/Qmdb/Mmb/Peaks.lean) relates the physical size guard, inverse position lookup and complete peak iterator to the model. [Children](../../lean/Qmdb/Mmb/Children.lean) checks the physical child positions. [Dfs](../../lean/Qmdb/Mmb/Dfs.lean) relates the extracted subtree reconstruction to the model, including its sibling cursor. [Grafting](../../lean/Qmdb/Mmb/Grafting.lean) checks the pending-chunk arithmetic and zero-bitmap decision. [Bagging](../../lean/Qmdb/Mmb/Bagging.lean) relates the forward inactive prefix and backward peak folds to the root preimage. Its extraction projects the two iterator loops into tail recursion on a finite cursor. The extraction scripts document the projection of Rust iterators, primitive operations and transparent types into the model.

[Coverage](../../lean/Qmdb/Mmb/Coverage.lean) proves that every selected plan for a nonzero chunk includes both the operation and the bitmap bytes, even when the preceding or following peaks are compressed. The proof uses the delayed-merge height formula to show that every grafted location lies in a peak of height at least eight.

[Raw](../../lean/Qmdb/Mmb/Raw.lean) checks a decoded proof's bit, digest widths and count, suffix presence and chunk digests, then substitutes the input fields into the program and compares the resulting root to the trusted digest. Its soundness theorem constructs both openings by induction on the same program. The verifier can run on opaque digests. [RawHeader](../../lean/Qmdb/Mmb/RawHeader.lean) proves that each accepted proof opens its root to its own dimensions. [Mmb](../../lean/Qmdb/Mmb.lean) connects the openings to an honest snapshot. The snapshot layout specifies its honest paths. At a zero graft, the field where a nonzero bitmap would appear contains the unwrapped node's eight-byte position.

Run `verification/qmdb/mmb/check.sh` in a checkout with the Lean dependencies prepared. It archives the pinned fork once into `.verification-tools/qmdb/tempo/<pin>`, builds one Rust example there with a single Cargo job, then runs the Lean comparison. The cached tree keeps its target directory, so later runs only rebuild the example when `trace.rs` changes. The script uses the local Git object for the pin and prints the fetch command when needed. It also regenerates the pin-specific Hax extractions and compares them to the checked-in Lean.

The Rust harness traces the exact SHA-256 calls made by the pinned `OperationProof::verify`. It derives a root using chosen sibling digests and replays the proof against that root. Lean independently consumes the same digests. The check compares the complete hash-input tree, the two projection paths and acceptance, and exercises changed operations, inactive chunks, substituted roots, extra or missing siblings and wrong suffix presence. It samples 932 accepted proofs at sizes from one to 777 leaves, including the 255/256/257 and 382/383/384 boundaries. This is a differential test of the pinned Rust implementation. The universally quantified soundness and coverage statements apply to the Lean reconstruction.

## Ordered maps and checkpoint composition

The ordered result is an optional value at a full key. The reference lookup replays the committed journal in append order. A later update replaces the earlier value and a delete removes it. The proof assumes a well-formed writer snapshot in which the activity bits identify the latest live updates, each live successor link is adjacent in the same key order, and the active commit bounds live locations by its floor. The operation and bitmap openings are tied to a single current root. A zero bitmap graft uses the underlying Merkle node, whose eight-byte position is distinguishable from a 32-byte bitmap chunk. [Journal and invariants](../../lean/Qmdb/Ordered.lean)

The production membership selector reconstructs the update from the requested key and value and the supplied successor. The exclusion selector authenticates either a strict cyclic gap or an active commit whose floor equals its own location. Hax extracts the selectors and their shared interval decision. Lean proves the selected operation and proof are exactly those used by the replay soundness theorem. The fixed encoding commits to the operation tag, ordered update fields, optional metadata, big-endian floor and zero padding. [Extracted selectors](../../lean/Qmdb/Ordered/Extraction.lean) · [Operation encoding](../../lean/Qmdb/Ordered/Encoding.lean)

A consumer can verify the decoded compressed proof using only its selected root, leaf count and inactive-peak count. Acceptance supplies an opening of those counts; equality of the selected current roots binds both counts to the committed database. Account and slot journals may have completely different sizes and histories. The outer SHA-256 commitment binds their two roots in order by constructor injectivity. Keccak-256 has a distinct unary constructor for application keys. Both hashes are ideal. [Header binding](../../lean/Qmdb/MmbHeader.lean) · [Header recovered from an accepted proof](../../lean/Qmdb/Mmb/RawHeader.lean) · [Root pair](../../lean/Commonware/Symbolic/RootPair.lean)

The one- and three-leaf examples construct the journal, bitmap, MMB layout and header and accept real compressed proof shapes for membership, singleton-gap exclusion and empty-commit exclusion. The proof boundary starts with decoded proof fields and a valid committed snapshot. Persistence, partition-index maintenance, checkpoint authentication and the concrete hash functions are outside that boundary. [Checked examples](../../lean/Qmdb/Ordered/Examples.lean)

With the Lean dependencies prepared, run `lake build Qmdb.CheckpointAudit` in `verification/lean`. The audit checks the imported checkpoint theorems for additional axioms and proof holes.
