# BLS signer attribution · Hax → DyLean

Active on `verify/qmdb-hax-dylean` in `.worktrees/qmdb-hax-dylean`. Run `bash verification/bls/check.sh` from the worktree, or `bash verification/check.sh` to check every target. It checks [Protocol.lean](Protocol.lean) against the exact Hax BLS revision recorded in the script, with the DyLean pin, Lean 4.35 compatibility patch and DyLean build that all targets share through [toolchain.sh](../toolchain.sh). Ignored `.lake/` holds exported source and build products. The Hax experiment documents regeneration of the Rust extraction.

The protocol uses DyLean reachability and logged events for signing, compromise and acceptance. The adversary can submit any signature derivable from the preceding events, including aggregate recombination and subtraction. Admission requires derivable key-specific proofs of possession. The guard calls the pinned extracted verifier. The theorem quantifies over **every reachable acceptance event** and produces a strictly earlier signing index for each protected signer and exact domain/message. A compromise after acceptance does not weaken the result. The honest-aggregate lemma shows that a reachable signing history permits acceptance of the corresponding aggregate.

The algebra and certified-key threat model draw on [Hofmeier et al.](https://arxiv.org/abs/2505.10316). The integer-coefficient abstraction is implemented in Lean, with distinct message and PoP inputs. No Tamarin theory or computational reduction is imported. Attacker availability is a protocol transition precondition with explicit deduction rules. Framing, hashing, pairing, group checks, registry identity binding and cached operands retain the Hax experiment’s boundary. Production Rust changes: zero.
